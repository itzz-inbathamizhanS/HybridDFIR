# Data Models & Configuration Specifications

This document exhaustively details the data contracts, JSON schemas, and configuration settings that bind the Hybrid Forensics Framework together.

## 1. Case Object Schemas (`src/config/data_models.json`)

The framework relies on strict JSON Schema validation to ensure that any data passed between modules (or generated by external integrations) conforms to the `CaseObject` schema. This structure is enforced by `src/core/case_manager.py`.

### 1.1 The `CaseObject` (Root Schema)

This is the top-level payload exported as `CASE_EXPORT_*.json`.

**Fields:**
- `case_metadata` (object): General information (Case ID, Analyst, Timestamps).
- `audit_logs` (array of `AuditLog`): Immutable chain-of-custody logging.
- `findings` (array of `Finding`): Individual threat detections.
- `evidence_graph` (array of `Relationship`): The relational mapping between findings.

### 1.2 The `Finding` Schema

Every threat detected by *any* module (Memory, Network, Persistence, DLL, Disk) must be normalized into a `Finding`.

**Fields:**
- `finding_id` (string): Unique identifier (e.g., `FND-12345678-ABCDEF`).
- `timestamp` (string, `date-time`): The exact UTC time the event was detected or occurred.
- `source_module` (string): Enum of `["memory", "disk", "network", "persistence"]`.
- `event_type` (string): Categorizes the finding (e.g., `"THREAT_DETECTED"`, `"CROSS_MODULE_THREAT"`).
- `description` (string): A human-readable, detailed description of the threat.
- `risk_score` (integer, `0-100`): The heuristic risk score. Capped at 100.
- `mitre_attack_ttps` (array of strings, optional): List of MITRE ATT&CK technique IDs (e.g., `["T1055", "T1071.001"]`).

### 1.3 The `Relationship` Schema

Defines how two findings connect in the Evidence Graph.

**Fields:**
- `source_id` (string): The originating `finding_id`.
- `target_id` (string): The target `finding_id`.
- `relationship_type` (string): Enum of `["TEMPORAL_LINK", "CONTRIBUTES_TO", "SPAWNED_BY", "INJECTED_INTO"]`.
- `confidence` (string): Enum of `["LOW", "MEDIUM", "HIGH", "CERTAIN"]`.

### 1.4 The `AuditLog` Schema

**Fields:**
- `timestamp` (string, `date-time`)
- `actor` (string): Usually "SYSTEM" or the analyst name.
- `action` (string): e.g., "CASE_CREATED", "MODULE_EXECUTION".
- `target` (string): e.g., "threat_scorer", "native_ram".
- `details` (string): Contextual logging data.

## 2. Configuration Settings (`src/config/settings.py`)

This file contains the global constants and air-gap directives used across the application.

- **`ALLOW_NETWORK_ACCESS`**: Hardcoded to `False`. Ensures no module makes outbound REST API calls.
- **`OFFLINE_MODE`**: Hardcoded to `True`.
- **`BASE_DIR`**: Automatically resolved root directory of the project.
- **`OUTPUT_DIR`**: `BASE_DIR / "output"`. All CASE containers and HTML reports are written here.
- **`HASH_CHUNK_SIZE`**: `65536`. Used for streaming SHA-256 hashes without memory exhaustion.

## 3. Schema Validation

The framework uses standard Python `jsonschema` validation to ensure every `CASE_EXPORT` payload is 100% compliant before saving it to disk, guaranteeing that SIEMs and the internal HTML generator never crash on malformed data.
