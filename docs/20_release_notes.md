# Release Notes

## Phase 1.1 — Native Live RAM Inspector (August 2026)

This release focuses on **zero-binary, driverless live memory inspection**, allowing analysts to perform advanced forensic analysis on endpoints where third-party drivers (like `winpmem`) are blocked by modern EDRs or Windows Security mechanisms.

### Core Features
- **Native Live RAM Analyzer (`src/capture/native_ram.py`)**: A new zero-binary memory scanner built entirely on native Win32 APIs via Python's `ctypes` (`kernel32`, `shell32`).
- **Heuristic Threat Detection**: Added heuristic logic to detect:
  - `RWX_SHELLCODE_INJECTION` (PAGE_EXECUTE_READWRITE)
  - `RWX_WRITECOPY_SUSPICIOUS` (PAGE_EXECUTE_WRITECOPY)
  - `LARGE_PRIVATE_EXECUTABLE` (>1MiB unbacked PAGE_EXECUTE_READ)
  - `RWX_GUARD_STAGED_PAYLOAD` (PAGE_GUARD modifiers)
- **JIT & AV Whitelisting**: The engine now intelligently suppresses false positives from known JIT compilers (V8, .NET CLR) and AV products (Windows Defender, etc.) by downgrading their risk score to 10.
- **Forensic Capture Engine (`src/capture/live_ram.py`)**: The `/capture` command now orchestrates a deep forensic acquisition:
  1. Scans all memory via the Native RAM Analyzer
  2. Uses `dbghelp.dll!MiniDumpWriteDump` to dump memory for processes with risk scores ≥ 50
  3. Bundles dumps and JSON scan results into a timestamped evidence directory
- **Driver Fallback**: The `/capture --driver` flag attempts a physical RAM dump using `winpmem.exe` first, gracefully falling back to native capture if blocked.
- **Interactive REPL Updates**: The `src/main.py` CLI orchestrator now supports `/scan`, `/capture`, and `/analyze` commands with a rich console interface.

### Enhancements
- **Data Schemas**: Unified the JSON schemas in `data_models.json` to formally define `CorrelatedEvent` outputs generated by the native RAM scanner.
- **Privilege Validation**: Added `shell32.IsUserAnAdmin()` checks to all capture modules. If run without elevated privileges, the framework halts and displays a rich error panel instead of crashing.
- **Test Suite**: Added mock-based testing for `test_memory.py` to test Volatility wrapper parsing without requiring a real Volatility installation on the CI runner.

## Phase 1.0 — Initial Release (August 2026)

The initial release of the Hybrid Forensics Framework, establishing the air-gapped, modular pipeline architecture.

### Features
- **Evidence Intake**: Chunk-based MD5 and SHA-256 hashing engine for verifiable chain-of-custody.
- **Disk Analysis**: Extractor for Windows SYSTEM registry hives and Prefetch files, parsing MAC timestamps securely.
- **Memory Analysis**: A wrapper around the `volatility3` CLI tool, parsing JSON output for process enumeration and injected code detection (`windows.pslist`, `windows.malfind`).
- **Correlation Engine**: A unified chronological timeline builder that merges disk events (Prefetch, Registry) with memory events (active processes). Includes a heuristic Threat Scorer that identifies suspicious file execution paths and payload activity.
- **Action Response**: Generates structured JSON reports for SIEM ingestion and self-contained HTML dashboards for offline analyst review.
- **Air-Gapped Design**: Guaranteed zero network egress logic; strict reliance on local toolchains.

### Known Limitations
- Disk analysis currently only parses the SYSTEM registry hive; SAM, SECURITY, and SOFTWARE are unsupported.
- Deep Prefetch binary parsing is not yet implemented (relies on filename parsing).
- Event logs (`.evtx`) are not collected.
- Volatility 3 is required for offline memory image analysis (`/analyze memory` mode).

### Roadmap for Phase 2.0
- MFT ($MFT) extraction and timeline merging
- Deep Windows Event Log correlation
- Yara rule integration for memory scanning
- Linux endpoint support
