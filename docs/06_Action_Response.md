# Action Response Module

> Module: `src/response/` — Automated Report Generation

---

## 1. Overview

The Action Response module is the final stage of the forensic pipeline. It is responsible for taking the central `CaseObject` state (metadata, audit logs, findings, and relationships) and packaging it into offline-accessible reports.

Adhering to the framework's air-gapped philosophy, this module writes all reports strictly to the local file system with zero external CDN dependencies.

---

## 2. Module Structure

```
src/response/
├── __init__.py                # Exports: ReportGenerator
└── report_generator.py        # JSON and HTML report generation engine
```

## 3. Core Components

### 3.1 `ReportGenerator` Class

**File:** `src/response/report_generator.py`

#### Constructor

```python
ReportGenerator(case_id: str)
```

| Parameter | Type | Description |
|---|---|---|
| `case_id` | `str` | The target Case ID (e.g., `CASE-20260910-A1B2C3`) |

Upon instantiation, the generator automatically resolves the isolated report directory for the case inside the framework's configured `OUTPUT_DIR` (default: `output/<case_id>/`).

#### `generate_json_report(case_data: dict) → str`

Saves the complete, raw `CaseObject` as a structured JSON file.

- **File created:** `CASE_EXPORT_<YYYYMMDD>_<HHMMSS>.json`
- **Contents:** The exact `case_data` dictionary generated by `CaseManager.get_case_info()`.
- **Returns:** Absolute path to the generated JSON file.

This file is heavily structured and typed according to JSON Schema `Draft-07`. It is intended for ingestion into upstream SIEMs, log aggregators, or further automated processing pipelines.

#### `generate_html_report(case_data: dict) → str`

Generates a self-contained, human-readable HTML dashboard for incident responders.

- **File created:** `forensic_report.html`
- **Contents:** A single-file HTML document with embedded CSS (Tailwind styles).
- **Returns:** Absolute path to the generated HTML file.

**HTML Features & Logic:**
- Fully offline — no external CDNs, web fonts, or remote JS libraries are referenced.
- Extracts `threat_findings` and auto-colors badges based on the `risk_score` (CRITICAL, HIGH, MEDIUM, LOW).
- Visualizes the **Evidence Graph** (Relationships). If `relationships` exist in the case data, it generates an interactive data table mapping the Source Finding to the Target Finding.
- Prints the MITRE ATT&CK TTP badges assigned during the cross-module correlation phase.

## 4. Pipeline Integration

The `ReportGenerator` is invoked at the very end of `src/main.py` when executing `--dashboard` or `--self-test`:

```python
from src.response.report_generator import ReportGenerator

# Retrieve unified case state
case_data = manager.get_case_info()

# Initialize generator
report_gen = ReportGenerator(case_id=manager.case_id)

# Generate both report formats
json_path = report_gen.generate_json_report(case_data)
html_path = report_gen.generate_html_report(case_data)

print(f"JSON Export: {json_path}")
print(f"HTML Dashboard: {html_path}")
```

## 5. Output Directory Structure

The framework keeps output strictly organized by Case ID to prevent cross-contamination between different evidence runs.

```text
hybrid-forensics-framework/
└── output/
    └── CASE-20260910-C7EF57/                # Secure Case Container
        ├── CASE_EXPORT_20260910_154211.json # Complete SIEM Payload
        └── forensic_report.html             # Human-readable dashboard
```
